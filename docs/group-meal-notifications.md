# 团购客饭接龙小程序订阅消息设计

## 1. 目标

在团购关键节点向用户、团长发送微信订阅消息，提升下单转化率、截单触达率与履约到达率。

目标覆盖场景：

- 下单成功确认
- 截单前提醒
- 团已截单通知
- 可取餐通知
- 配送中通知
- 订单完成通知
- 缺货/变更通知

## 2. 设计原则

- 仅在用户授权订阅后发送。
- 每个场景的发送需具备去重机制。
- 优先发送对用户体验和履约最关键的信息。
- 所有发送请求与结果需落库，便于排查失败原因。
- 模板字段尽量复用，降低运营配置复杂度。

## 3. 通知场景清单

## 3.1 订单创建成功通知

### 场景编码

`order_created`

### 触发时机

订单创建成功，状态进入 `joined`。

### 发送对象

- 下单用户

### 发送目的

- 告知用户已成功接龙
- 提醒查看截单时间与履约信息

### 模板字段建议

| 字段 | 示例 |
|---|---|
| 团名称 | 3号楼午餐接龙 |
| 商品摘要 | 番茄牛腩饭等 2 件 |
| 下单时间 | 2025-01-01 09:20 |
| 截单时间 | 2025-01-01 10:30 |
| 履约方式 | A栋一楼前台自提 |

### 发送频率

- 每个订单仅发送一次

## 3.2 截单前提醒

### 场景编码

`group_cutoff_reminder`

### 触发时机

在截单前固定时间点触发，例如：

- 截单前 60 分钟
- 截单前 15 分钟

MVP 建议仅保留一个节点：截单前 15 分钟。

### 发送对象

- 已下单用户
- 团长

### 发送目的

- 提醒用户尽快确认或修改订单
- 提醒团长关注截单与汇总

### 模板字段建议

| 字段 | 示例 |
|---|---|
| 团名称 | 3号楼午餐接龙 |
| 截单时间 | 10:30 |
| 当前状态 | 即将截单 |
| 提示文案 | 如需改单请尽快处理 |

### 发送频率

- 每团每用户每提醒节点一次

## 3.3 截单通知

### 场景编码

`group_cutoff`

### 触发时机

- 团长手动截单成功
- 系统定时截单成功

### 发送对象

- 该团已下单用户
- 团长

### 发送目的

- 告知用户订单已锁定
- 告知团长可查看汇总并安排履约

### 模板字段建议

| 字段 | 示例 |
|---|---|
| 团名称 | 3号楼午餐接龙 |
| 截单结果 | 已截单 |
| 履约安排 | 11:30-12:00 A栋一楼前台 |
| 跳转文案 | 点击查看订单/汇总 |

## 3.4 可取餐通知

### 场景编码

`order_ready_for_pickup`

### 触发时机

订单状态变更为 `ready_for_pickup`。

### 发送对象

- 自提订单用户

### 发送目的

- 提醒用户在规定时间到自提点取餐

### 模板字段建议

| 字段 | 示例 |
|---|---|
| 团名称 | 3号楼午餐接龙 |
| 自提点 | A栋一楼前台 |
| 自提时间段 | 11:30-12:00 |
| 订单摘要 | 番茄牛腩饭 x2 |
| 取餐提示 | 请凭订单页面核销码领取 |

## 3.5 配送中通知

### 场景编码

`order_delivering`

### 触发时机

订单状态变更为 `delivering`。

### 发送对象

- 配送订单用户

### 发送目的

- 提醒用户餐品正在配送，关注电话与签收

### 模板字段建议

| 字段 | 示例 |
|---|---|
| 团名称 | 3号楼午餐接龙 |
| 配送状态 | 配送中 |
| 配送地址 | 科技园1号楼1202 |
| 联系方式 | 13800001111 |
| 温馨提示 | 请保持电话畅通 |

## 3.6 订单完成通知

### 场景编码

`order_completed`

### 触发时机

订单状态进入 `completed`。

### 发送对象

- 下单用户

### 发送目的

- 通知订单已完成
- 引导用户查看积分到账、再次下单

### 模板字段建议

| 字段 | 示例 |
|---|---|
| 团名称 | 3号楼午餐接龙 |
| 完成时间 | 2025-01-01 12:05 |
| 积分奖励 | 20 积分 |
| 引导文案 | 欢迎再次参团 |

## 3.7 缺货/变更通知

### 场景编码

`order_exception`

### 触发时机

后台对订单执行缺货、换货、减项等异常处理时触发。

### 发送对象

- 受影响订单用户

### 发送目的

- 告知用户订单有变更
- 引导查看详情或联系团长

### 模板字段建议

| 字段 | 示例 |
|---|---|
| 团名称 | 3号楼午餐接龙 |
| 异常类型 | 商品缺货 |
| 处理结果 | 已为您减项并补发 5 元券 |
| 处理说明 | 请查看订单详情 |

## 4. 团长侧通知建议

除用户通知外，可补充以下团长专属通知：

### 4.1 开团结果确认

场景编码：`leader_group_published`

### 4.2 截单提醒

场景编码：`leader_cutoff_reminder`

### 4.3 汇总生成通知

场景编码：`leader_summary_ready`

MVP 可先不单独申请模板，复用业务后台提醒或站内提醒。

## 5. 模板申请建议

微信订阅消息模板建议控制在 4~6 个，避免审批与维护成本过高。

推荐 MVP 最小模板集合：

1. 下单成功通知
2. 截单提醒/截单通知（二选一也可合并）
3. 可取餐通知
4. 配送中通知
5. 订单异常通知

## 6. 触发规则设计

## 6.1 事件与发送映射

| 事件 | 场景编码 | 触发对象 | 备注 |
|---|---|---|---|
| OrderCreated | order_created | 用户 | 创建订单成功后 |
| GroupCutoffSoon | group_cutoff_reminder | 用户/团长 | 定时任务触发 |
| GroupCutoff | group_cutoff | 用户/团长 | 截单成功后 |
| OrderReadyForPickup | order_ready_for_pickup | 用户 | 自提订单 |
| OrderDelivering | order_delivering | 用户 | 配送订单 |
| OrderCompleted | order_completed | 用户 | 完成履约 |
| OrderExceptionHandled | order_exception | 用户 | 缺货/换货/减项 |

## 6.2 发送时序建议

### 下单成功

- 同步创建订单
- 异步投递消息任务
- 消息系统检查授权记录与模板配置
- 成功发送后写入发送记录

### 截单提醒

- 定时任务扫描 `cutoff_at`
- 找出将要截单的团
- 拉取已订阅用户集合
- 批量投递发送任务

### 履约通知

- 当后台执行状态流转接口时
- 触发异步事件
- 消息系统消费事件并发送

## 7. 去重策略

每类消息都需要去重，推荐唯一键如下：

| 场景 | 去重键 |
|---|---|
| order_created | user_id + order_id + scene_code |
| group_cutoff_reminder | user_id + group_id + scene_code + reminder_time |
| group_cutoff | user_id + group_id + scene_code |
| order_ready_for_pickup | user_id + order_id + scene_code |
| order_delivering | user_id + order_id + scene_code |
| order_completed | user_id + order_id + scene_code |
| order_exception | user_id + order_id + scene_code + exception_version |

## 8. 授权与合规说明

### 8.1 用户授权要求

- 用户必须在小程序中主动点击订阅授权。
- 授权结果需要立即记录到服务端。
- 若用户拒绝授权，不得尝试强行发送。

### 8.2 内容合规要求

- 内容需与用户操作直接相关。
- 不得发送营销骚扰内容。
- 通知文案需客观明确，不夸张、不诱导。
- 仅在必要频次内发送，避免过度打扰。

### 8.3 数据留痕

服务端需记录：

- 用户 ID
- 场景编码
- 模板 ID
- 请求参数
- 发送结果
- 失败原因
- 发送时间

## 9. 失败处理策略

### 9.1 常见失败原因

- 用户未订阅
- 模板 ID 未配置
- 模板参数不合法
- 微信接口限流
- token 失效

### 9.2 处理建议

- 可重试错误：限流、临时网络失败
- 不可重试错误：未订阅、模板无效、参数错误
- 对连续失败场景要做告警

## 10. 后台配置项

后台建议支持以下配置：

- 场景编码
- 模板 ID
- 模板名称
- 是否启用
- 默认触发条件
- 是否允许手工补发

## 11. 日志字段建议

通知发送日志建议包括：

- `scene_code`
- `template_id`
- `user_id`
- `group_id`
- `order_id`
- `send_status`
- `request_payload`
- `response_payload`
- `fail_reason`
- `retry_count`
- `sent_at`

## 12. MVP 建议上线顺序

第一阶段：

- 下单成功通知
- 截单通知
- 可取餐通知/配送中通知

第二阶段：

- 截单前提醒
- 订单完成通知
- 缺货变更通知
