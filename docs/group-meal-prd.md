# 团购客饭接龙小程序 PRD

## 1. 产品目标

面向微信小程序场景，提供一套围绕“团长发起团购活动、用户接龙下单、截单汇总、配送/自提履约、会员营销复购”的闭环产品。

MVP 目标：

- 团长可快速发起团购活动并分享。
- 用户可在团内完成接龙下单。
- 系统可在截单后自动形成商品汇总。
- 履约支持自提或配送。
- 支持库存限量、优惠券、积分与消息通知。
- 后台可配置商品、团购活动、订单、会员与通知模板。

## 2. 角色定义

### 2.1 普通用户

能力范围：

- 浏览团购活动
- 查看团详情与商品库存
- 下单、查看订单、取消待支付/待确认订单
- 选择地址或自提点
- 使用优惠券、查看积分
- 接收消息通知

### 2.2 团长

能力范围：

- 发起团购活动
- 配置截单时间、履约方式、取餐点/配送规则
- 查看本团订单列表
- 截单与查看汇总
- 分享团链接、海报
- 发送开团提醒与履约通知

### 2.3 商家管理员

能力范围：

- 商品与规格管理
- 库存调整
- 团模板与团管理
- 订单管理与履约操作
- 自提点与配送规则配置
- 会员积分/优惠券配置
- 消息模板配置与发送记录追踪

## 3. 核心业务流程

### 3.1 用户接龙下单流程

1. 用户进入首页，查看可参加团购活动。
2. 进入团详情，浏览套餐/菜品、库存、截单时间、履约方式。
3. 选择商品规格、份数、备注，进入确认页。
4. 选择配送地址或自提点与时间段。
5. 选择优惠券，系统计算优惠金额。
6. 创建订单，库存即时占用。
7. 下单成功后展示订单详情、履约信息与通知订阅入口。

### 3.2 团长开团与截单流程

1. 团长进入发起团页面。
2. 选择团模板或手动选择商品。
3. 设置团标题、截单时间、履约方式、展示规则。
4. 发布后生成分享链接/分享卡片。
5. 截单时，系统锁定订单，生成汇总页。
6. 汇总页按商品/规格统计数量，供备餐、分拣与配送。

### 3.3 履约流程

#### 自提模式

1. 订单状态进入“待取餐”。
2. 用户收到可取餐通知。
3. 到店/到点后，团长或管理员核销订单。
4. 订单变更为“已完成”。

#### 配送模式

1. 订单状态进入“配送中”。
2. 用户收到配送提醒。
3. 配送完成后管理员确认送达。
4. 订单变更为“已完成”。

## 5. 状态机设计

### 5.1 团状态机

- draft：草稿
- published：已发布
- ongoing：进行中
- cutoff：已截单
- fulfilled：履约中/履约完成
- closed：已关闭

状态流转：

- 草稿 -> 已发布
- 已发布 -> 进行中
- 进行中 -> 已截单
- 已截单 -> 履约中/履约完成
- 任意可运营状态 -> 已关闭

### 5.2 订单状态机

- pending_confirm：待确认
- joined：已接龙
- cutoff_locked：截单锁定
- ready_for_pickup：待取餐
- delivering：配送中
- completed：已完成
- cancelled：已取消
- closed：系统关闭

状态流转：

- 待确认 -> 已接龙
- 已接龙 -> 截单锁定
- 截单锁定 -> 待取餐
- 截单锁定 -> 配送中
- 待取餐 -> 已完成
- 配送中 -> 已完成
- 待确认/已接龙 -> 已取消
- 超时未处理 -> 已关闭

### 5.3 库存状态机

- available：可售
- reserved：已占用
- released：已释放
- deducted：已扣减
- adjusted：人工调整

规则：

- 创建订单即占用库存
- 取消订单释放库存
- 截单后可按业务选择保留占用或转正式扣减
- 人工补库存或减库存需记录日志

## 6. 异常流程

### 6.1 截单时下单

场景：用户在截单瞬间提交订单。

处理规则：

- 服务端以数据库时间为准校验团状态与截单时间
- 已超过截单时间则拒绝创建订单
- 返回“活动已截单，请参与下一团”

### 6.2 下单时库存不足

场景：用户提交订单前库存还有，提交时被其他用户抢完。

处理规则：

- 服务端再次校验库存
- 若不足则返回最新可购数量
- 前端提示用户调整数量重新提交

### 6.3 商品下架

场景：团中商品被后台下架。

处理规则：

- 已成团商品保留历史快照
- 未下单用户不可再购买该商品
- 已下单订单不受影响

### 6.4 用户改单

场景：用户修改已下单商品数量。

处理规则：

- 仅在团配置允许且未截单时可修改
- 修改后重新计算库存占用和优惠
- 修改需保留审计记录

### 6.5 缺货处理

场景：截单后备餐阶段发现缺货。

处理规则：

- 管理员可将订单项标记为缺货
- 支持换货、减项、人工补偿券
- 必须记录处理结果并通知用户

### 6.6 自提/配送信息缺失

场景：用户下单后地址或自提点信息不完整。

处理规则：

- 创建订单时强校验，不允许缺失
- 已创建订单若后续规则变更导致不可履约，需后台人工介入调整

## 7. 关键字段规则

### 7.1 优惠券使用规则

- 每单仅使用一张优惠券（MVP）
- 券适用范围可配置：全场券、商品券、团活动券
- 已截单后不可变更用券

### 7.2 积分规则

- 按订单实付金额赠送积分
- 已完成后入账
- 取消/关闭订单不赠送积分

### 7.3 接龙展示隐私规则

- 默认昵称脱敏
- 手机号不展示
- 备注默认不公开
- 接龙明细支持后台/团长开关配置

## 9. MVP 验收标准

- 用户可完整完成接龙下单闭环。
- 团长可发起团并在截单后看到汇总。
- 自提与配送两种履约方式可选。
- 库存不足时不会超卖。
- 支持至少一种优惠券和积分赠送。
- 关键节点支持订阅消息触达。
- 后台可完成商品、团、订单与消息配置。
